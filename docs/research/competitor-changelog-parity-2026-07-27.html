Competitive release audit · 2026-07-27

The best updates converge on continuity.

Codex, Claude Code, ChatGPT Desktop, Claude Desktop, Hermes Agent, and T3 Code are shipping toward the same core: durable project context, resumable work, visible agent activity, fast navigation, and trustworthy local execution. Doolittle already had much of the execution layer. This wave closes the most visible continuity gaps.

Product direction

Keep Doolittle repo-native and local-first. Adopt competitor interaction patterns where they improve continuity, but do not fake cloud sync, vendor-only remote execution, or protocol support that the runtime does not actually provide.

What changed in the market

Codex

Projects became multi-folder workspaces

  • Primary and related local folders per project.
  • Paginated history, search, names, subagents, and memories.
  • Branching on edit/retry, voice, plugins, and richer review.
ChatGPT Desktop

Search and recents became global

  • Unified recent work with sort, filter, and pin.
  • Search across chats, projects, and files.
  • Work mode, scheduled tasks, plugins, and multi-repo projects.
Claude Code

Long-running work became more durable

  • Background sessions, worktree isolation, and reliable resume.
  • Nested agents, budgets, concurrency, and live tool timing.
  • Context controls, trust boundaries, and clearer recovery.
Claude Desktop

Projects became persistent workspaces

  • Local project files, instructions, and memory.
  • Computer use, browser work, notifications, and schedules.
  • Persistent mobile threads and private/incognito sessions.
Hermes Agent

The agent UI became immediate

  • Per-thread drafts, detached windows, and model presets.
  • Live reasoning, tool activity, subagent panes, and fast streams.
  • Durable background delivery, approvals, themes, and diff scale.
T3 Code

Repository workflow moved into the sidebar

  • Branch-aware threads, worktrees, PR actions, and diffs.
  • Draft lifecycle, snooze/archive, prompt stash, and file mentions.
  • Project palette, provider wizard, persistence, and updates.

Status describes the integrated Doolittle checkout, not a marketing promise. “Next” means the feature needs a deeper runtime or platform capability and should not be represented as complete.

Implementation boundary

  • Local-first continuity Drafts, queues, pins, project selection, and search work without a cloud account.
  • One real project model Projects remain repository-backed runtime scopes with optional related files and folders, not decorative chat folders.
  • Safe protocol surfaces MCP status and discovery are visible, while tool invocation remains inside established approval-aware execution paths.
  • Truth over checkbox parity Remote sync, mobile continuity, and vendor-hosted features stay on the ledger until Doolittle owns the required backend.
