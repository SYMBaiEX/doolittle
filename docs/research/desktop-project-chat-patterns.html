Competitive product study · 2026-07-27

Projects should be where chats live.

Codex, ChatGPT, Claude, Hermes Agent, and T3 Code use different names, but their strongest pattern is the same: choose a durable workspace first, then create and resume conversations inside it.

Doolittle’s project unit should be a local repository.

The project owns its root path, instructions, sources, and chat history. A detached “General” scope remains available, but it is a deliberate choice—not the default path into coding work.

The three useful archetypes

01 / Repo native

Codex, Claude Code, T3 Code

The local folder is the source of truth. Sessions are execution contexts attached to a concrete working directory.

02 / Knowledge workspace

ChatGPT, Claude Desktop

Projects carry durable instructions and files across chats. Users can organize or move existing conversations into them.

03 / Workspace tree

Hermes Agent

The sidebar exposes the real hierarchy—project, repo, worktree, session—without requiring a separate management surface.

Doolittle product decisions

  1. Project equals repository.

    Selecting a local folder creates or reopens the matching project and restarts the private runtime in that repository.

  2. New conversation starts with a project picker.

    Pinned and recent projects appear first, with explicit paths for choosing a new repository or starting a detached General chat.

  3. Projects own chat history in the left rail.

    Expandable project rows show their latest chats. Each row has an inline plus that starts a conversation in that repo.

  4. Management remains secondary.

    The full manager handles instructions, sources, pinning, moving, and archiving; it is not required for routine switching.

  5. Preserve chat-to-project identity everywhere.

    Local optimistic session overlays must retain projectId so a conversation cannot visually or behaviorally fall out of its repository while streaming.
